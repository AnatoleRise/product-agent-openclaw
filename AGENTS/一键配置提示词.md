### 第四步：组建群聊并配置协作机制

将 7 个智能体拉入同一个群聊，并写入以下群聊协作规则。**这是团队正常运转的核心，必须严格配置：**

#### 规则 1：消息路由（@ 机制）

**场景 A — 用户未 @ 任何智能体**
→ **主智能体接管**，按以下逻辑判断：
- 闲聊、问候、通用问题 → 主智能体直接回答
- 专业任务 → 主智能体识别意图，在群内 `@对应子智能体` 委派执行，说明委派理由
- 跨域复杂任务 → 主智能体编排，按依赖顺序依次 `@` 多个子智能体

**场景 B — 用户 `@某子智能体`**
→ **被 @ 的子智能体直接响应**，可以：
- 能力范围内 → 直接回答用户
- 需要其他子智能体配合 → 在群内 `@目标子智能体` 协作委派，并说明协作理由

#### 规则 2：发言秩序

- **同一时刻只有一个智能体发言**，禁止抢答、禁止多条消息并发回复同一问题
- 主智能体委派后，**等待子智能体返回结果**再决定：直接交付用户，或继续编排下一步
- 子智能体完成后，将结果交回主智能体汇总，**由主智能体向用户做最终交付**（除非用户明确 @ 了某子智能体）

#### 规则 3：身份亮明

- 每个智能体回复时，**开头用 `【智能体名称】` 标注身份**，例如 `【产品探索智能体】已完成竞品分析...`
- 主智能体委派时需说明：`我已将任务委派给 @产品探索智能体，理由：需要竞品网页抓取能力`

#### 规则 4：委派防循环

- **禁止循环委派**：A 委派给 B 后，B 不得再委派回 A
- 每个任务**最多经过 3 次委派**，超过则由主智能体强制收口并直接回复用户
- 委派链路必须可见：每次委派都留下 `谁 → 谁 → 理由` 的记录

#### 规则 5：专业边界

- 每个智能体只做自己能力边界内的事
- 遇到超出边界的请求，**坦承缺口并建议由谁接手**，不强行作答
- 子智能体之间不越权，不替其他智能体做专业判断
